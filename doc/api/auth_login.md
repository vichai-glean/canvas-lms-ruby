# Canvas API Direct Login

This document describes the direct login API endpoint that allows client applications to authenticate users with email/password credentials and receive OAuth2-style access tokens without using browser redirects.

## Endpoint

```
POST /api/v1/auth/login
```

## Purpose

This endpoint enables:
- Direct authentication for mobile apps and other client applications
- Stateless API authentication without browser sessions
- OAuth2-compatible token responses
- Integration with Canvas's existing authentication system

## Request

### Headers
```
Content-Type: application/json
```

### Parameters

| Parameter | Type   | Required | Description |
|-----------|--------|----------|-------------|
| `email`   | string | Yes      | User's email address or login ID |
| `password`| string | Yes      | User's password |

### Example Request

```bash
curl -X POST https://your-canvas-domain/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "user@example.com",
    "password": "userpassword"
  }'
```

## Response

### Success Response (200 OK)

```json
{
  "access_token": "1~abc123def456...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "unrestricted",
  "user": {
    "id": 123,
    "name": "John Doe",
    "email": "user@example.com",
    "login_id": "user@example.com",
    "global_id": "10000000000001",
    "avatar_url": "https://secure.gravatar.com/avatar/..."
  },
  "canvas_region": "us-east-1"
}
```

### Error Responses

#### 400 Bad Request - Missing Parameters
```json
{
  "error": "authentication_failed",
  "error_description": "Missing email parameter"
}
```

#### 401 Unauthorized - Invalid Credentials
```json
{
  "error": "authentication_failed", 
  "error_description": "Invalid email or password"
}
```

#### 403 Forbidden - Account Issues
```json
{
  "error": "authentication_failed",
  "error_description": "User account is not active"
}
```

#### 503 Service Unavailable
```json
{
  "error": "authentication_failed",
  "error_description": "Authentication service temporarily unavailable"
}
```

## Using the Access Token

After successful authentication, use the `access_token` in subsequent API requests:

```bash
curl -H "Authorization: Bearer 1~abc123def456..." \
  https://your-canvas-domain/api/v1/users/self
```

## Security Considerations

### CSRF Protection
- This endpoint skips CSRF protection for stateless operation
- Only accessible via POST requests with JSON content
- No browser sessions are created

### Rate Limiting
- Standard Canvas API rate limiting applies
- Failed authentication attempts are logged and may be rate limited

### Token Scope
Tokens generated by this endpoint have **unrestricted access** to all Canvas API endpoints that the authenticated user has permission to access. This means:
- Full read/write access to all API endpoints
- No scope limitations (equivalent to a manually created personal access token)
- Access is still limited by the user's actual permissions within Canvas

### Token Expiration
- Tokens may expire based on Canvas configuration
- Check the `expires_in` field for token lifetime
- Use refresh tokens if provided

## Configuration Options

### Token Scope Configuration
The API endpoint can be configured to provide different levels of access by modifying the `default_api_scopes` method in `ApiAuthController`:

```ruby
def default_api_scopes
  # Option 1: Unrestricted access (current default)
  nil
  
  # Option 2: All explicitly defined scopes
  # TokenScopes.all_scopes
  
  # Option 3: Limited specific scopes
  # [
  #   'url:GET|/api/v1/users/self',
  #   'url:GET|/api/v1/courses',
  #   'url:POST|/api/v1/courses/:id/assignments'
  # ]
end
```

**Unrestricted Access (Default)**: Tokens have access to all API endpoints the user has permission for. This is equivalent to personal access tokens created through the Canvas UI.

**Explicit All Scopes**: Tokens are granted all currently defined API scopes. New API endpoints added to Canvas would require updating the scope list.

**Limited Scopes**: Tokens are restricted to only specific API endpoints. Most secure but requires careful scope selection.

## Implementation Notes

### Authentication Provider Support
- Works with Canvas native authentication
- Supports LDAP authentication when configured
- Does not support OAuth or SAML providers (use standard OAuth flow instead)

### Multi-Factor Authentication (MFA)
- Does not currently support MFA flows
- Users with MFA enabled should use the standard browser-based login

### Account Restrictions
- Respects Canvas account settings and user permissions
- Suspended or deleted accounts will be rejected
- Account-specific authentication providers are honored

## Example Client Implementation

### JavaScript/Node.js
```javascript
async function loginToCanvas(email, password) {
  const response = await fetch('/api/v1/auth/login', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({ email, password })
  });
  
  if (!response.ok) {
    const error = await response.json();
    throw new Error(error.error_description);
  }
  
  const data = await response.json();
  // Store access_token for future API calls
  localStorage.setItem('canvas_token', data.access_token);
  return data;
}

// Use the token for API calls
async function getCurrentUser(token) {
  const response = await fetch('/api/v1/users/self', {
    headers: {
      'Authorization': `Bearer ${token}`
    }
  });
  return response.json();
}
```

### Python
```python
import requests

def login_to_canvas(base_url, email, password):
    url = f"{base_url}/api/v1/auth/login"
    data = {
        "email": email,
        "password": password
    }
    
    response = requests.post(url, json=data)
    response.raise_for_status()
    return response.json()

def get_current_user(base_url, token):
    url = f"{base_url}/api/v1/users/self"
    headers = {"Authorization": f"Bearer {token}"}
    
    response = requests.get(url, headers=headers)
    response.raise_for_status()
    return response.json()

# Usage
try:
    auth_data = login_to_canvas("https://your-canvas-domain", "user@example.com", "password")
    token = auth_data["access_token"]
    user = get_current_user("https://your-canvas-domain", token)
    print(f"Logged in as: {user['name']}")
except requests.exceptions.HTTPError as e:
    print(f"Authentication failed: {e}")
```

## Best Practices

1. **Secure Token Storage**: Store access tokens securely and never expose them in client-side code
2. **Error Handling**: Implement proper error handling for all possible response codes
3. **Token Refresh**: Monitor token expiration and implement refresh logic when available
4. **Logging**: Log authentication attempts for security monitoring
5. **Input Validation**: Validate email and password inputs before sending requests

## Migration from Browser-Based Auth

This endpoint complements but does not replace Canvas's standard OAuth2 flow. Use this endpoint for:
- Mobile applications
- Server-to-server integrations
- Simple client applications

Continue using the standard OAuth2 flow for:
- Web applications with browser sessions
- Third-party integrations requiring user consent
- Applications needing specific scopes beyond the defaults
